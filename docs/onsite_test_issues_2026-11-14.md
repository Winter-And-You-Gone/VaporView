## 001：AI-8 只有一个通道更新

- 用户现象：AI-8 页面只有一路数据，预期希望观察八路。
- 已确认原因：当前 HCD2 使用 schema 2；`0x661C` 选择 CH1～CH8 中的一个，复位默认 CH1。下位机持续轮询该通道；当前固件已撤回自动八通道扫描。
- 上位机保留八个显示槽位，但不会复制所选通道数据填满其他槽位，也不会后台反复停用/切通道来模拟自动扫描。
- 当前可用操作顺序：禁用 AI-8 → 修改并读回 `0x661C` → 重新启用。该顺序只用于明确的手动测试，本次排查未执行切换。
- 后续处理：若要求八路持续更新，需要明确下位机轮询/数据标识方案，完成 RTL、协议兼容、上位机和实板验证后再加载新 BIT。当前不将该能力视作已实现。
- 依据：本地 `c76b4d5b` 中的 `docs/fpga_hcd2_adaptation_20261114.md`；下位机 `ai8_modbus_rs485.v` 的单个 `channel` 寄存器及 `ai8_poll_core.v` 的所选通道地址计算。

## 002：AI-8 模块 `0x66` 新错误 `0x40`

### 现场证据

- 13:10:02.085，sequence 12：AI-8 连接成功，已收到设备有效数据。
- 13:10:05.024，sequence 24：启动等待 3 秒后仍异常；模块 `0x00000066`，新增及累计错误均为 `0x00000040`。
- 该管理事件的 source 为 `0x46`，模块页为 `0x66`（寄存器基址 `0x6600`），事件状态字为 `0x00000C83`。其中 AI-8 专用 STATUS.bit1 为 online，bit7 为汇总错误；它可以通信在线且同时报错。

### 已确认原因与边界

`0x40` 是 bit6，定义为 `ERR_DEVICE_REPORTED_ERROR`。AI-8 RTL 在采集结果的 `core_alarm != 0` 或 `core_host[9:8] != 0` 时锁存该位；设温读回不匹配或 Modbus exception 等命令结果也可以置位。它不是“只有一个通道”的错误，也不能直接解释为 USB 或串口断开。

本次单条事件没有携带 AI-8 的完整 alarm/control/host 字，不能进一步断言是探头断线、输入超量程或哪种仪表报警。粘滞错误记录曾发生的错误，不单独证明当前仍在报同一种故障；启动提示表示宽限期结束时未通过完整健康判断。

### 说明书核对与现场补充（2026-11-14）

用户补充：实际只接了两路输入，怀疑其余六路未接导致报警。本机已找到 `D:/Project/说明书/AI-8+系列多回路智能温控器+使用说明（8xx8g+8xx8精度5以下）.pdf`，与下位机 `Docs/【资料】FPGA设备接入手册/6-AI-8+系列多回路智能温控器+使用说明（8xx8g+8xx8精度5以下）.pdf` 的 SHA-256 完全相同，为 `d505369af30cf33ebb5022a2566634cf0aa2490278e85573f5f967a15e3f148e`，共 47 个 PDF 页面。

核对完整相关页并渲染查看报警处理页后，确认以下手册定义（括号中先为 PDF 页序，再为页脚页号）：

- 第 23 页（22/47），5.1 通道参数：`In01..In96` 的个位 1..4 选择输入规格组，个位为 0 关闭该路测量。未用通道可按实际配置关闭；不能把 `In` 与选择传感器类型的输入组参数 `InP` 混为一谈。
- 第 40～41 页（39/47～40/47），报警状态 `0x0680..0x06AF`：每个寄存器装两个通道，高字节为奇数通道、低字节为偶数通道；通道报警 bit0 为输入错误或超量程 `oral`，bit1..4 为 HA/LA/dHA/dLA，bit5..7 为备用。
- 第 44 页（43/47），主机状态 `0x0851`：bit8 表示系统故障，bit9 表示全局报警；两者含义不同。
- 第 46 页（45/47），第 8 节“报警及故障处理”：任何一路报警条件成立都会产生额外的全局公共报警，可从 `0x0851.bit9` 读出；对于未使用的输入通道，手册建议关闭该通道。

约 13:31～13:32，通过正在运行的 GUI 的 FPGA → 传感器页只读观察，确认：

| 项目 | 现场读值 | 判断 |
| --- | --- | --- |
| 所选通道 | `0x661C=1`（CH1） | 当前仍采集 CH1，本次未改变通道 |
| PV / SP | `911.0°C / 40.0°C` | PV 同时伴随输入报警，不能作为实际温度 |
| 当前通道 alarm | 十进制 `1`，即 `0x01` | CH1 本身输入错误/超量程，不只是从全局报警推测 |
| 主机 host | 十进制 `532`，即 `0x0214` | bit9=1，全局报警；bit8=0，本次读值没有系统故障标志 |
| VLP flags | `0x11` | 含 error 标志；页面的“测量有效”字样不能作为仪表无报警的证据 |

说明书与当前 RTL 的机制一致：`ai8_poll_core.v` 读取所选通道报警，同时始终读取仪表全局 `0x0851`；`ai8_modbus_rs485.v` 把 `core_alarm != 0` 或 `core_host[9:8] != 0` 汇总为 FPGA 的 `0x40`。所以即使所选通道正常，其他仍启用但未接输入的通道也能通过全局报警触发 `0x40`。上位机 `FpgaSensorAdapter.cpp` 也把该全局报警纳入 `alarmActive`。

结论：用户提出的“只接两路、其余未接输入触发报警”有手册依据，并且与现场全局报警位一致。但当前所选 CH1 的单通道输入错误也已置位，不能直接把全部报警归到其余六路。如果所接两路不包含 CH1，当前表现符合正在查询未接通道；如果 CH1 是已接的两路之一，仍需核对 CH1 的接线、传感器类型和输入配置。本次未遍历八路，未确认两路实接编号，也没有验证其余六路的 `In` 启用状态，因此不把六路逐一报错作为已读回事实。

### 现场证据

用户补充设备已拆除后，接收超时有明确现场解释，不再执行供电、接线、模式、计数或有效测距复验。以后重新接入再按新现场单独验收。

## 004：TFA 连接失败提示延迟约 202 秒

- 关联问题：003。启用至失败的日志间隔为 `202.400 s`，不是界面中启动健康检查使用的 3 秒。
- 已确认代码原因：`FpgaDeviceController::confirmConnection` 为不同设备选择轮询间隔地址，但未覆盖 TFA（source `0x45`）。它将 `pollAddress` 回落为 `0`，仍计算 `max(8000, 3 * registers_[pollAddress] + 5000)`。
- `readAll()` 会读取地址 `0x0000`；当前下位机 `system_registers.v` 在该地址返回系统 ID `0x00010101`（65793），不是毫秒间隔。因此理论等待为 `3 * 65793 + 5000 = 202379 ms`，与本次实测 `202400 ms` 一致。
- 影响：延迟连接失败提示；不能解释或修复 TFA 串口本身没有有效数据的问题。其他没有映射到轮询间隔地址的设备也应在修复时检查同一路径。
- 修复方向：对没有毫秒轮询间隔的设备使用明确的默认期限；只有合法的轮询间隔地址参与计算。TFA 的 `0x653C` 单位为 FPGA tick，不能未经换算当毫秒使用。
- 状态：保留独立软件问题记录，按用户本轮忽略 TFA 的要求不继续处理。若后续修复，应覆盖“无有效数据按正确期限失败”和“期限内收到数据成功”的定向回归，并在 `build/Release` 验证后交付。
