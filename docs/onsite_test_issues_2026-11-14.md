## 001：AI-8 只有一个通道更新

- 用户现象：AI-8 页面只有一路数据，预期希望观察八路。
- 已确认原因：当前 HCD2 使用 schema 2；`0x661C` 选择 CH1～CH8 中的一个，复位默认 CH1。下位机持续轮询该通道；当前固件已撤回自动八通道扫描。
- 上位机保留八个显示槽位，但不会复制所选通道数据填满其他槽位，也不会后台反复停用/切通道来模拟自动扫描。
- 当前可用操作顺序：禁用 AI-8 → 修改并读回 `0x661C` → 重新启用。该顺序只用于明确的手动测试，本次排查未执行切换。
- 后续处理：若要求八路持续更新，需要明确下位机轮询/数据标识方案，完成 RTL、协议兼容、上位机和实板验证后再加载新 BIT。当前不将该能力视作已实现。
- 依据：本地 `c76b4d5b` 中的 `docs/fpga_hcd2_adaptation_20261114.md`；下位机 `ai8_modbus_rs485.v` 的单个 `channel` 寄存器及 `ai8_poll_core.v` 的所选通道地址计算。

## 002：AI-8 模块 `0x66` 新错误 `0x40`

### 现场证据

- 13:10:02.085，sequence 12：AI-8 连接成功，已收到设备有效数据。
- 13:10:05.024，sequence 24：启动等待 3 秒后仍异常；模块 `0x00000066`，新增及累计错误均为 `0x00000040`。
- 该管理事件的 source 为 `0x46`，模块页为 `0x66`（寄存器基址 `0x6600`），事件状态字为 `0x00000C83`。其中 AI-8 专用 STATUS.bit1 为 online，bit7 为汇总错误；它可以通信在线且同时报错。

### 已确认原因与边界

`0x40` 是 bit6，定义为 `ERR_DEVICE_REPORTED_ERROR`。AI-8 RTL 在采集结果的 `core_alarm != 0` 或 `core_host[9:8] != 0` 时锁存该位；设温读回不匹配或 Modbus exception 等命令结果也可以置位。它不是“只有一个通道”的错误，也不能直接解释为 USB 或串口断开。

本次单条事件没有携带 AI-8 的完整 alarm/control/host 字，不能进一步断言是探头断线、输入超量程或哪种仪表报警。粘滞错误记录曾发生的错误，不单独证明当前仍在报同一种故障；启动提示表示宽限期结束时未通过完整健康判断。

### 后续定位与验收

通过现有连接读取所选通道 `0x661C`、仪表状态 `0x6628`（host/control/alarm）、原始 PV/SP `0x6658`、命令结果 `0x664C`、成功轮询及超时/CRC计数，结合 AI-8 面板/说明书解码。先保存原值，不以清错作为修复。报警 PV 不作为正常温度；通信在线与测量健康分别验收。

上位机定位入口：`src/ground/devices/FpgaDeviceController.cpp::checkStartupWarnings`；下位机：`fpga/rtl/sensors/ai8_modbus_rs485.v`。

## 003：TFA1500-L 接收超时、未确认到有效距离

### 现场证据

- 13:10:01.558，sequence 10：TFA 通道已启用，等待有效数据。
- 13:10:04.583，sequence 22：模块 `0x65`（基址 `0x6500`、source `0x45`）新增及累计错误 `0x01`，事件状态 `0x83`。
- 13:13:23.958，sequence 25：连接失败，`reason_code=NO_VALID_SAMPLE`，`module_error=1`、`module_status=131`（`0x83`）。截至该条日志没有 TFA `VALID_SAMPLE` 连接成功记录。

### 已确认原因与边界

下位机错误 bit0 `0x01` 为 `ERR_TIMEOUT`。TFA 在串口报文间隔超时，或运行时超过接收看门狗时间没有解析到完整帧时置位。`0x83` 表示 enabled=1、状态机 ready=1、汇总 error=1，online(bit4)=0；启用成功与有效测距是两个条件。

当前证据支持 TFA 接收链路没有及时获得可用帧、上位机没有确认有效测距，尚不能区分供电、接线、传感器输出模式、波特率、命令响应或间歇报文。有效完整帧但无效回波对应另一错误位 `0x40`，不能把本次 `0x01` 直接归因于无目标。

### 后续定位与验收

核对 TFA 供电、CON21/原 LF 接线、实际 HF/LF 模式及串口参数；通过现有连接保存 `0x6510/0x6514` 的波特率/模式、`0x6528` 收帧数、`0x652C` 校验错误、`0x6530` 无效回波、`0x653C` 超时阈值、`0x6540` 超时计数和 `0x655C` 格式错误计数的增量。HCD2 复位默认 HF 模式、500000 baud，但本次尚未读取现场实际值，不能将默认值当作现场读回。

验收需要同时看到完整收帧、有效距离持续更新、错误计数不再增长；改变参数或接线后的结果单独追加记录。

## 004：TFA 连接失败提示延迟约 202 秒

- 关联问题：003。启用至失败的日志间隔为 `202.400 s`，不是界面中启动健康检查使用的 3 秒。
- 已确认代码原因：`FpgaDeviceController::confirmConnection` 为不同设备选择轮询间隔地址，但未覆盖 TFA（source `0x45`）。它将 `pollAddress` 回落为 `0`，仍计算 `max(8000, 3 * registers_[pollAddress] + 5000)`。
- `readAll()` 会读取地址 `0x0000`；当前下位机 `system_registers.v` 在该地址返回系统 ID `0x00010101`（65793），不是毫秒间隔。因此理论等待为 `3 * 65793 + 5000 = 202379 ms`，与本次实测 `202400 ms` 一致。
- 影响：延迟连接失败提示；不能解释或修复 TFA 串口本身没有有效数据的问题。其他没有映射到轮询间隔地址的设备也应在修复时检查同一路径。
- 修复方向：对没有毫秒轮询间隔的设备使用明确的默认期限；只有合法的轮询间隔地址参与计算。TFA 的 `0x653C` 单位为 FPGA tick，不能未经换算当毫秒使用。
- 状态：本次仅记录。后续修复应覆盖“无有效数据按正确期限失败”和“期限内收到数据成功”的定向回归，并在 `build/Release` 验证后交付。

## 005：双 DLIA 数据质量错误 `0x80`

- 13:10:03.778，sequence 19：模块页 `0x50`（DLIA0/source `0x30`、基址 `0x5000`）新增及累计错误 `0x80`，事件 STATUS=`0x93`。
- 13:10:03.805，sequence 20：模块页 `0x51`（DLIA1/source `0x31`、基址 `0x5100`）同样为 `0x80`，STATUS=`0x93`。
- 错误 bit7 对应 `ERR_DATA_FORMAT`。当前 `dila_core.v` 在接受样本时，如任一 `sample_flags` 非零，或当前模式要求 WMS 相位且 capture tag 的相位有效位为 0，会锁存 bit7，并标记周期 partial。
- 日志未包含触发样本的 flags、模式和 capture tag，不能仅凭 `0x80` 判定是 ADC 饱和、输入标记异常还是启动时缺少相位标签，也不能断言两个通道的具体触发原因相同。
- 后续需结合 ADC/DLIA 原始帧质量标志、模式、WMS 相位/周期标签和输入饱和等计数定位。13:10:04.246 的 ADC/DLIA“连接成功”只确认 CONTROL 读回，不证明完整周期质量通过；异常周期不得参与有效定标。
- 状态：已登记，未复测或清错。
