## 4.18 补全计划（软件验证完成，待现场验收）

**交付目标。** 完成一次采集后，操作员能用上位机导出数据。另一位开发者拿到 SDK、说明和这次任务的 Session 副本后，能在独立程序中查询同一批记录，导出到指定目录，并复核数量、时间与测量值。大纲要求这两条路径都能实际操作。

## 4.19 原补全计划（HTTPS 版历史方案）

**交付目标。** 地面上位机能设参、启停实际采集并显示机载处理结果。同时，一台外部测试机能主动连到地面网关，通过 HTTPS 查数据、下发一项已开放的控制命令，通过 WebSocket 连续接收实时测量与状态。

| 步骤 | 拟开展的工作 | 完成依据 |
| --- | --- | --- |
| 1. 核对目标平台及现有链路 | 记录约定机载机、地面机的操作系统、架构、软件版本、设备及数传方式。先在模拟环境走通地面设参、采集启停、状态回读、机载 H2/H1 与峰值处理、地面波形预览和网关取数。 | 用同一通道及可关联的时间或周期编号，将机载特征、地面显示、网关收到的帧对上。明确预览抽稀和原始完整波形的区别，列出还需实机复核的项目。 |
| 2. 在地面端开放 HTTPS 查询与控制 | 建议扩展地面 GUI 内置网关，复用现有遥测、命令白名单和回执处理。拟提供状态/最新测量查询、提交控制命令、按命令 ID 查询结果三个操作。外部工具连接地面端配置的地址，监听、证书和调用权限独立于现有向服务器上传的配置。 | 独立工具在校验证书后查询状态或数据，再执行一项白名单内的控制动作。建议在有效定标已选、设备就绪时演示“启动记录”，核对同一命令的受理、SkyCore 回执以及随后出现的录制状态和 Session。另测拒绝、超时和重复请求。 |
| 3. 提供实时测量与状态订阅 | 在同一地面网关提供 WSS（加密 WebSocket）入口，首版推送测量和设备状态。消息说明设备、通道、时间、序号、值、单位和质量。订阅复用已接收的遥测，限定单客户端队列并让丢帧或断线可识别。 | 外部客户端能连续收到两类消息，将代表性测量和状态变化与地面端对上。断开、重连和慢客户端测试期间，采集、记录和地面显示仍能继续。 |
| 4. 在约定平台完成联调 | 用真实设备连机载 SkyCore、地面 VaporView 与内置网关，从独立测试机连接 HTTPS 和 WSS。地面 GUI 做设备设参和实际采集启停，API 单独验证获准开放的控制指令。 | 逐项填写 A.19 六行，记录平台配置、起止时间、设备状态、代表性波形及特征、命令 ID 与结果、实时消息和异常情况。4.19 按实际时长记录，大纲明确的“至少 5 分钟”属于 4.17。 |

现有接入点见 [地面遥测服务](../src/ground/devices/GroundTelemetryService.h)、[网关遥测和命令处理](../src/ground/gateway/GatewayService.cpp)及[命令白名单设置](../src/ground/main/GatewaySettingsDialog.cpp)。Windows Release 现使用 Qt 6.10.1 的 HttpServer 和 WebSockets 模块。原 HTTPS 方案依赖 TLS 后端与证书。当前局域网操作见上方复测步骤。

**审阅重点**是约定的两端平台、外部工具连接哪个地面地址、可开放哪条控制命令。建议沿用已有“启动记录”命令做 API 演示，同时由 GUI 单独验收 FPGA 采集启停。两个计划可以复用一次现场采集的 Session 标识和设备记录，A.18 与 A.19 分别填写。
