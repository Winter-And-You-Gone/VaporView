依据《测试大纲261117_合稿_无批注.docx》正文 4.16–4.19 及附录 A.16–A.19。首次核对日期为 2026-11-19，代码基线为 `main` 的 `d3db122`。本表按四张原始记录表的 20 个检查项跟踪 VaporView 的实现和现场证据。

| --- | --- | --- |

| 4.17 实时数据处理 | 部分实现 | 已有采集中的自动预处理和初始浓度计算，仍需补齐正式浓度处理并取得连续采集至少 5 分钟的实测记录。 |
| 4.18 数据存储、导出及接口 | 部分实现 | 已有 Session 存储和多种界面导出。仓库内未找到可供独立程序调用的 Session SDK 交付物及导出一致性记录。 |

## 4.16 实时采集数据可视化（合同 2.7.1）

大纲 2.2、2.5 给出了两路数据的含义。816 nm 开放路径通道结合测距、定标和温压信息，输出目标路径上的平均水汽柱浓度。1368 nm 原位通道输出局地水汽浓度，再将不同高度的有效样本与同期位置、姿态关联，形成水汽浓度廓线。

| A.16 检查项 | 当前实现 | 待补功能或现场核验 |
| --- | --- | --- |
| 水汽柱浓度 | 部分实现。816 nm 通道已按定标文件计算和显示初始浓度。 | 补齐测距、温压及测量位置关联，在采集中观察开放路径平均浓度随有效测量更新。 |
| 原位水汽浓度 | 部分实现。1368 nm 通道能输出初始浓度、单位及有效状态。 | 补齐温压修正，核验原位测量结果、时间和对应位姿。 |
| 辅助参数 | 已实现显示入口。温度、湿度、压强、测距、三维位置和温控状态可在相应面板查看。 | 按正文在场地内移动设备，逐项检查接收及更新。记录表列有湿度，正文另要求温控状态。 |
| 水汽浓度廓线 | 仓库未找到按高度组织并实时显示浓度廓线的功能。 | 将各高度的有效原位浓度与测量时刻配对，显示并核对廓线。 |
| GIS地图展示 | 部分实现。实时地图接收导航位置、姿态和定位质量。历史 Session 可按峰值、湿度、温度或压强着色。 | 实时接入辅助测量和浓度，与对应位置关联。现场加载测试区域地图，核验设备移动时有无错位或停滞。 |

## 4.18 补全计划（待审阅）

**交付目标。** 完成一次采集后，操作员能用上位机导出数据。另一位开发者拿到 SDK、说明和这次任务的 Session 副本后，能在独立程序中查询同一批记录，导出到指定目录，并复核数量、时间与测量值。大纲要求这两条路径都能实际操作。

| 步骤 | 拟开展的工作 | 完成依据 |
| --- | --- | --- |
| 1. 确认开放数据范围 | 先核实项目是否另有 SDK。建议首版覆盖 Session 元信息、导航与温湿压及测距、原始波形（含 FPGA 成对 H1/H2）、周期特征与质量，以及已录制的浓度结果。逐类列出来源文件、时间基准、单位、缺失值和可导出格式。 | 形成一份开放字段表。注明哪些数据取自完整机载 Session，地面 Session 实际保存了哪些数据。当前初始浓度保留“未温压补偿”标记，正式浓度产品按 4.16/4.17 的交付版本接入。 |
| 2. 核验保存和上位机导出 | 对同一已完成任务逐类重开原始、处理和辅助数据，走现有原始解析器、轨迹和历史浓度导出入口。仅补字段表中没有可用入口或输出缺字段的项目。 | 一张清单能从每种数据追到源文件、界面操作和可重新打开的导出文件，覆盖 A.18 的前两行。 |
| 3. 交付供独立程序使用的 SDK | 建议先做只读 C++ SDK，复用现有格式读取、波形索引和历史浓度读取逻辑。提供打开 Session 目录、列出可用类别、按类别和时间段遍历、按帧读取波形、导出到指定目录的接口。提供版本化包、公共头文件、构建接入说明及一个命令行示例。 | 从仓库外的示例工程只依赖交付包及声明的运行依赖即可构建和运行。用例包含缺少可选流的旧 Session、大波形按帧读取、同时间戳多条记录，以及损坏数据的可识别错误。 |
| 4. 独立对账并完成现场记录 | 用预先确定内容的测试样本验证接口，再用一次实采 Session 复核。对照值从原始 CSV 行、DAT 记录头与选定帧样本、浓度记录中独立取得。 | 同一数据类别和时间范围内，源数据与 SDK 导出的记录数、时间戳及序号逐项一致。代表性字段核对通道、波形点数及采样值、峰值、单位和质量标志，浮点文本按声明精度核对。保存差异清单、SDK/软件版本、Session 标识和 A.18 记录编号。 |

优先复用 [SessionLoader](../src/ground/session/SessionLoader.h)、[统一 RAW DAT 读取接口](../src/shared/session/UnifiedRawDat.h)、[波形读取接口](../src/ground/session/SessionWaveformRepository.h)和[历史浓度读取接口](../src/ground/calibration/RecordedConcentrations.h)。**审阅重点**是 SDK 的使用方、接入语言和首版开放范围。若已有外部 SDK，先用步骤 3、4 的独立程序和对账方法评估覆盖，再确定需补的接口。

## 4.19 补全计划（待审阅）

**交付目标。** 地面上位机能设参、启停实际采集并显示机载处理结果。同时，一台外部测试机能主动连到地面网关，通过 HTTPS 查数据、下发一项已开放的控制命令，通过 WebSocket 连续接收实时测量与状态。

| 步骤 | 拟开展的工作 | 完成依据 |
| --- | --- | --- |
| 1. 核对目标平台及现有链路 | 记录约定机载机、地面机的操作系统、架构、软件版本、设备及数传方式。先在模拟环境走通地面设参、采集启停、状态回读、机载 H2/H1 与峰值处理、地面波形预览和网关取数。 | 用同一通道及可关联的时间或周期编号，将机载特征、地面显示、网关收到的帧对上。明确预览抽稀和原始完整波形的区别，列出还需实机复核的项目。 |
| 2. 在地面端开放 HTTPS 查询与控制 | 建议扩展地面 GUI 内置网关，复用现有遥测、命令白名单和回执处理。拟提供状态/最新测量查询、提交控制命令、按命令 ID 查询结果三个操作。外部工具连接地面端配置的地址，监听、证书和调用权限独立于现有向服务器上传的配置。 | 独立工具在校验证书后查询状态或数据，再执行一项白名单内的控制动作。建议在有效定标已选、设备就绪时演示“启动记录”，核对同一命令的受理、SkyCore 回执以及随后出现的录制状态和 Session。另测拒绝、超时和重复请求。 |
| 3. 提供实时测量与状态订阅 | 在同一地面网关提供 WSS（加密 WebSocket）入口，首版推送测量和设备状态。消息说明设备、通道、时间、序号、值、单位和质量。订阅复用已接收的遥测，限定单客户端队列并让丢帧或断线可识别。 | 外部客户端能连续收到两类消息，将代表性测量和状态变化与地面端对上。断开、重连和慢客户端测试期间，采集、记录和地面显示仍能继续。 |
| 4. 在约定平台完成联调 | 用真实设备连机载 SkyCore、地面 VaporView 与内置网关，从独立测试机连接 HTTPS 和 WSS。地面 GUI 做设备设参和实际采集启停，API 单独验证获准开放的控制指令。 | 逐项填写 A.19 六行，记录平台配置、起止时间、设备状态、代表性波形及特征、命令 ID 与结果、实时消息和异常情况。4.19 按实际时长记录，大纲明确的“至少 5 分钟”属于 4.17。 |

现有接入点见 [地面遥测服务](../src/ground/devices/GroundTelemetryService.h)、[网关遥测和命令处理](../src/ground/gateway/GatewayService.cpp)及[命令白名单设置](../src/ground/main/GatewaySettingsDialog.cpp)。当前 Windows Release 所用 Qt 安装目录有 Qt Network，未发现 Qt HttpServer、Qt WebSockets 的 CMake 包。**实施前先在目标平台确认服务端依赖、TLS 后端及部署方式**，再选用可维护的 HTTPS/WSS 实现。

**审阅重点**是约定的两端平台、外部工具连接哪个地面地址、可开放哪条控制命令。建议沿用已有“启动记录”命令做 API 演示，同时由 GUI 单独验收 FPGA 采集启停。两个计划可以复用一次现场采集的 Session 标识和设备记录，A.18 与 A.19 分别填写。
