# 直连与 FPGA 中转 UI 适配及功能缺失

## 修复计划与验收条件

| 顺序 | 项目 | 验收条件 |
|---|---|---|
| 1 | 远程直连 / FPGA 路径切换 | 经现有数传 TCP 下发配置，切换不关闭数传；等待最终应用结果，拒绝时恢复已确认的路径；超时读回天空配置，不自动重发 |
| 2 | 两页来源与参数显示 | 设备配置页和 FPGA 页共用 FPGA 气压来源；温湿度固定 SHT45；保存的直连来源、串口和波特率保持独立 |
| 3 | 首页连接入口与状态 | 本地与远程均可从首页建立 FPGA 连接，再启用指定设备；最终连接读回成功才继续，失败或超时不自动重试；区分通道启用与有效测量 |
| 4 | AI8 和 EPSILON 操作能力 | 保留数据显示；不支持的参数操作在 UI 和设备会话两层禁止，不提示用户改接串口 |
| 5 | RTK / RTCM | FPGA 模式禁用启动、串口测试、串口探测和参数下发；切换进入 FPGA 时停止原 RTK / GGA 服务；保留 NTRIP 配置供直连使用 |
| 6 | 回归与交付 | 覆盖本地/远程 × 直连/FPGA，Release 构建、相关回归和跨 SkyCore 全量回归；无实板时仅报告软件验证 |

## 共用入口的行为

首页与设备配置页的逐设备按钮复用同一个路由入口。本地直连打开本机设备；远程直连由 SkyCore 打开天空端设备。本地 FPGA 打开 USB 并启用指定 VLP1 source；远程 FPGA 通过数传 TCP 请求 SkyCore 建立 USB 会话，再启用指定 source。SkyCore 是远程 USB 的唯一所有者。单设备停用不关闭 USB 或数传。

“通道已启用”来自 FPGA CONTROL 寄存器，不能证明传感器在线或测量有效。测量有效性、数据新鲜度和数据帧频率分别由实际测量及质量信息决定。

首页波形原始信号按钮控制 RAW 上传；二次谐波按钮控制共同 ADC/DLIA 采集。停止共同采集也停止 RAW，两个按钮不是两个独立的采集引擎。

## 配置模型与当前写入边界

设备配置页在 FPGA 路径显示 FPGA 寄存器读回的串口波特率、轮询间隔换算频率，I²C 设备显示 I²C；未就绪时显示不可用。TFA 输出频率由设备决定。它们不写入保存的直连预设，页面也不再提供“可编辑但不会下发”的输入。

“启用”复选框保存的是直连启动预设，在 FPGA 路径只读保留；FPGA 通道实际启停使用同行的设备操作按钮，并根据 CONTROL 寄存器读回更新状态。界面测试模式仍允许 EPSILON、RTK 的原有内存模拟操作，不代表真实 VLP1 增加了这些下发能力。

这是**上位机尚未提供通用传感器参数提交事务**的边界，不是下位机完全没有配置寄存器。现有 VLP1 文档已定义 PTB baud/poll、EPSILON baud/消息掩码、BMP/SHT poll、TFA baud 等字段；直接写这些字段仍需逐设备停用、范围约束、提交、恢复及读回验证。当前设备配置页只读显示，不能据此声称它们已经可写。AI8 的地址、通道、轮询、超时和重试使用 FPGA 页现有的停用后提交流程。

气压来源选择仅改变 PTB210 `0x0040` / BMP390 `0x0043` 的标准化数据显示来源；不改传感器串口参数，不重启 USB 或采集。远程选择经 SkyConfig 下发并由 SkyCore 使用，不能只改地面标签。FPGA 温湿度来源为 SHT45 `0x0044`，不能把直连 HMP3 预设显示为实际 FPGA 来源。

## 当前 VLP1 功能缺失

依据同级 FPGA 仓库 `Docs/protocol/FPGA_HOST_PROTOCOL_V1.0.md`、`HOST_HANDOFF_20261001.md` 和 VaporView 当前控制接口；独立的 VFLP 设计稿不是当前实现依据。

| 缺失项 | 当前已支持 | 下位机需要补充的能力 | 上位机处理 |
|---|---|---|---|
| AI8 完整参数页 / 恢复出厂 | 测量 PV、SP 等状态；目标温度设置及仪表读回确认 | 明确的通道/组/全局参数读写、恢复出厂命令，仪表响应与读回结果、超时及错误语义 | 参数页命令禁用并说明 VLP1 不支持；FPGA 页轮询、设温流程可用 |
| EPSILON 参数命令 | FDILink 接收、导航/姿态/状态数据显示 | 包频率、安装杆臂、融合参数、GNSS/DGNSS 设置、校准/重启等下行及参数回读 | 参数操作禁用，保留导航显示；不使用另一个串口绕过 FPGA |
| RTCM 注入 EPSILON | 直连模式的本机串口输出或数传到 SkyCore 转发 | VLP1 RTCM 注入命令、目标 UART、分片/流控、写入统计及设备/传输失败语义 | FPGA 模式阻止启动和串口旁路；远程天空端继续拒绝此操作 |
| HMP3、RD105 经 FPGA 接入 | SHT45、AI8 分别有自己的 source；直连 HMP3/RD105 独立保留 | 如需要这些实体设备，新增明确的 source、版本、命令及数据 schema | 不把 SHT45/AI8 冒充为 HMP3/RD105；RD105 连接入口禁用 |

缺失功能不能通过取消灰化实现。需先扩展当前 FPGA/VLP1 契约和固件，再补上位机命令、质量/错误处理与回读测试。

## 实机检查

- 数传连接保持期间往返切换两种设备路径，核对天空端实际路径及设备关闭/打开顺序。
- 从远程首页连接单个 FPGA 设备，确认只存在一个 USB 所有者；USB 连接失败时不继续发设备启用命令。
- 两页切换气压来源，分别核对标准化压力读数、频率和记录源；USB 会话及采集不重启。
- 通道启用但拔掉传感器时，不把启用状态当作有效测量。
- FPGA 模式点击或直接调用禁用操作，不打开本机/天空端旁路串口；返回直连后恢复原配置及可用操作。

完整现场验收及凭据/原始证据保留要求见 [FPGA 实机验收清单](fpga_hardware_validation.md)。

## 本轮软件验证（2026-10-14）

- 在 VS/MSVC Developer 环境执行 `cmake -S . -B build/Release` 和 `cmake --build build/Release --config Release -- -j2`；保留 osgEarth ON，构建成功。
- 本地/远程来源与预设隔离、远程切换成功/拒绝、数传连接保留、首页 USB 连接失败/手动重试/最终就绪后启用、RTK 旁路阻止，以及 AI8/EPSILON 会话能力回归均通过。真实 VLP1 协议模拟器和天空端来源切换回归通过；界面测试模式的内存模拟操作回归通过。
- 在 100% 字体缩放、62 逻辑像素紧凑侧栏下检查设备配置的 FPGA / 直连 Qt 渲染快照；临时截图和导出代码已移除。主窗口布局及独立数据查看器测试通过。
- 完成 133 项全量 CTest 和失败项复测；综合结果为 130 项通过、2 项失败、1 项跳过。仍失败的是 `combination_navigation_page_test` 的组合导航概览标题宽度断言和 `main_window_map3d_open_test` 的 3D 地图打开耗时断言，不包含在本轮功能修复中。更新重启器标准权限分支复测通过，管理员分支因未提升权限而跳过。

这些结果验证软件路由和模拟流程，尚未完成实板、真实 USB 驱动分支、真实数传或传感器的现场验收。
