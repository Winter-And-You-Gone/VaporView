# AI-8288 实机交接文档

## 1. 文档目的

本文档记录 AI-8288 实机与 VaporView 当前代码的对比结果，供后续会话、现场联调和代码维护直接使用。

本文档对应的实机型号为：

`AI-8288D92J0G71G71S2-24VDC`

本轮操作全部为 Modbus-RTU 功能码 `03H` 只读请求。没有执行 `06H` 或 `10H` 写入，没有修改 Addr、bAud、Srun、Loc 或任何控制参数。

## 3. 型号解析

根据说明书的型号规则，用户给出的型号可以解析为：

| 型号段 | 含义 | 当前结论 |
| --- | --- | --- |
| `8288` | 8 通道，0.3 级，非隔离输入 | 与代码的 8 通道模型一致 |
| `D92` | 导轨安装，无显示和按键，通过通信或 E85 配置 | 与用户型号一致，软件不能仅凭寄存器验证机械外形 |
| `J0` | 三线制热电阻输入 | 与当前通道 1 的 Pt100 读数相符 |
| 第一个 `G71` | 4 路隔离 NPN 主输出 | 说明书定义存在，未做物理输出带载测试 |
| 第二个 `G71` | 4 路隔离 NPN 辅助输出 | 说明书定义存在，未做物理输出带载测试 |
| `S2` | 固定 RS485 Modbus-RTU | COM1 实测可正常通信 |
| `24VDC` | 24 V 直流供电 | 由用户型号提供，未通过软件验证 |

设备返回的型号特征寄存器 `0x0853` 为 `0x218A`。说明书没有提供该数值与完整型号字符串之间的映射表，所以不能仅凭 `0x218A` 验证 `D92/J0/G71/G71/S2` 每一个后缀。

## 4. COM1 通信实测

### 4.1 连接环境

- Windows 串口：`COM1`
- USB 转串口芯片：Silicon Labs CP210x USB to UART Bridge
- Windows 端口状态：正常
- 实测打开参数：19200 baud、8 数据位、无校验、1 停止位
- Modbus 站号：1

曾对说明书列出的波特率 `4800/9600/19200/38400/57600/115200`，以及无校验/偶校验、1/2 停止位组合进行只读探测。只有 19200 得到有效的型号特征响应。需要注意：设备寄存器不保存停止位，串口容错也可能使不同停止位组合得到响应，因此“1 个停止位”主要由当前 Windows 端口设置确认，而不是由设备寄存器确认。

## 6. 状态与报警

### 6.1 报警寄存器 `0x0680-0x0683`

原始值为：

`0x0001, 0x0101, 0x0101, 0x0101`

说明书定义每个字节对应一个通道，bit 0 为输入错误。因此：

- 通道 1：无输入错误
- 通道 2-8：均置输入错误位

这与通道 1 读到 `30.0`、其余通道读到 `911.0` 的结果一致。后续现场确认应检查通道 2-8 是否实际接入传感器、传感器类型是否匹配以及接线极性。

### 6.2 控制状态寄存器 `0x06C0-0x06C3`

原始值为：

`0x0101, 0x0101, 0x0101, 0x0101`

按说明书的高低字节规则解码，8 个通道均为：

- bit 0 = 1：非自整定/APID
- bit 1 = 0：未停止

因此设备当前通道控制状态正常运行，但全局 `Srun=1` 的语义仍未确定。

### 6.3 高分辨率 PV `0x0660-0x066F`

已读取原始 16 位字，但说明书没有清楚说明 32 位组合顺序、符号处理和缩放方式。当前项目没有使用该区域，后续不要将它直接换算成温度，也不要据此修改普通 PV 处理。

## 7. 说明书、代码和实机之间的未决项

### 7.1 `Srun=1` 未定义

说明书列出的运行状态主要是 `0`、`15` 和 `9655`，实机返回 `1`。当前 UI 只提供这三个值，因此全局页面存在“读取到 1、保存时回落到 0”的风险。

相关代码：

- UI 运行状态选项：[`src/ground/widgets/Ai8TemperatureControllerPanel.cpp`](../src/ground/widgets/Ai8TemperatureControllerPanel.cpp)
- 全局页读取和写入：[`src/sky/devices/Ai8TemperatureControllerCollector.cpp`](../src/sky/devices/Ai8TemperatureControllerCollector.cpp)

在确认 `1` 的设备语义前，不应通过当前全局页面保存运行状态。

### 7.2 J0 输入类型码存在选择歧义

实机 `InP1=21`，当前代码将 21 显示为 Pt100。说明书输入表还列出：

- `22`：Pt100，`-200.0..+300.0 °C`
- `23`：Pt1000，`-200.0..+300.0 °C`，J0/J2
- `24`：`0..2000 Ω`，J0/J2

说明书没有明确说明该 J0 型号的三线 Pt100 应使用通用码 21 还是 J0 专用范围码 22。当前 UI 暴露了 21 和 23，但没有 22 和 24。需要以设备原厂配置说明、实物传感器范围或已知温度点继续确认。

### 7.3 停止位未存储在设备寄存器

当前设备按 COM1 的 Windows 配置使用 8N1。代码也固定使用 `SerialConfig::N81`。说明书允许 1 或 2 个停止位，但只读寄存器无法区分两者；后续若开放串口参数编辑，需要把设备切换时序和主机重连流程作为独立实机测试。

### 7.4 型号特征字没有官方映射

`0x0853=0x218A` 只能证明设备返回了一个型号特征字。当前代码只记录数值，不会将它与用户输入的完整型号比较，也无法验证两个 `G71` 输出模块的物理形态。

### 7.5 说明书地址范围自相矛盾

协议概览处写站号范围 `0..80`，全局参数表又出现 `0..88`。当前 UI 使用 `1..88`。这台设备地址为 1，不受影响，但新增地址校验时不能只引用其中一处文字。

### 7.6 当前代码没有覆盖全部参数

协议头已定义主要地址，但采集器和 UI 只覆盖其中一部分：

- 通道页未显示 `Pn`、`HA`、`LA`、`SV` 等完整通道参数
- 输出页未显示 `dHA`、`dLA`、`OHE`、`SPL`、`SPH`
- 全局页未显示 `Adn`、`ACH`、各报警公共参数、`EHYS`、主状态、型号特征和序列号
- 实时轮询只读取普通 PV 和控制状态，没有读取报警寄存器、主状态和高分辨率 PV

代码与说明书的基础地址、符号缩放、报警字节映射和控制状态位映射基本一致，但“协议已定义”不等于“页面已经覆盖”。

## 8. 后续会话的安全操作规则

1. 连接该设备优先使用 `COM1 @ 19200, 8N1, Modbus 地址 1`。
2. 初次联调只使用功能码 `03H` 读取 `0x0853`、`0x0600-0x0607`、`0x0680-0x0683` 和 `0x06C0-0x06C3`。
3. 不要把通道 2-8 的 `PV=911.0` 当作有效温度；先处理输入错误报警。
4. 未确认 `Srun=1` 语义前，不要通过当前全局页面保存参数。
5. 不要写入 `0x0840/0x0841`，除非已经准备好设备切换通信参数后的主机重连流程。
6. 不要写入 `0x0660` 高分辨率 PV 区，也不要修改 `0x0856-0x085F` 扩展寄存器。
7. 修改任何参数时只改一个字段，写入后立即用 `03H` 回读，并记录原始值、解码值和设备状态。
8. 任何现场日志、截图、导出包和测试样例不得提交到 Git；本文件只保留必要的寄存器快照和结论。

## 9. 建议的后续修复与验收标准

### 优先级 P0：避免误写 `Srun`

- 读取到未识别的运行状态时，UI 应显示原始值并禁止保存，或明确保留原始值。
- 增加回归测试：实机返回 `Srun=1` 时，读取后保存其它全局字段不能把 `Srun` 改成 0。

### 优先级 P1：补齐实机诊断信息

- 在只读诊断页显示 `0x0853`、序列号、主状态、报警寄存器和控制状态。
- 显示通道 `In/Sc/On/Pn/HA/LA/SV` 以及输出 `dHA/dLA/OHE/SPL/SPH`。
- 保留未知寄存器的原始十六进制值，不要在没有说明书依据时强行解码。

### 优先级 P1：确认 J0 输入码

- 使用已知 Pt100 温度点分别确认 21 和 22 的量程、负温度和三线制补偿行为。
- 在确认前不要自动把用户型号 `J0` 转换为 22、23 或 24。

### 优先级 P2：完善型号和协议校验

- 收集原厂对 `0x218A` 的型号特征字映射。
- 将站号范围冲突记录为兼容性规则，明确 UI、协议和说明书的最终采用范围。
- 若未来开放偶校验或停止位切换，必须加入串口重连和通信恢复的实机测试。

## 10. 一句话结论

这台设备已经确认可以在 `COM1 / 19200 / 8N1 / 地址 1` 下稳定读取，代码的基础 Modbus 地址和常用参数缩放基本正确；当前最危险的未决项是实机 `Srun=1` 未被说明书和 UI 覆盖，最明显的覆盖缺口是报警、完整通道参数、完整输出参数和全局扩展字段没有进入当前页面。
