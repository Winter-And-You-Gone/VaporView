# TEC103 双 GPIO 温控接入

现场两台控制器已通过只读命令分别返回 `TEC=103`、`FPV=4370`。LC0/LC1 是 FPGA 的原始 UART 通道名称，不是仪表型号；上位机将两个物理口映射为原位和遥测温控，每台仪表均访问内部 `TC1`，不能把第二台当作第一台的 `TC2`。

| 界面通道 | FPGA UART / 模块 ID | FPGA TX → 仪表 RX | 仪表 TX → FPGA RX |
|---|---|---|---|
| 原位 / TC1 | LC0 `0x6800 / 0x00480100` | CON11-5 | CON11-7 |
| 遥测 / TC1 | LC1 `0x6900 / 0x00490100` | CON11-6 | CON11-8 |

两口均使用 TTL `38400 / 8N1`，电平应兼容 FPGA 的 3.3V，并有公共参考地。连接时在 UART 停用且空闲的状态写入并核对波特率和格式，再启用通信。连接、读取参数和周期采集不会修改仪表目标温度、输出使能或 PID；断开只停止通信，不改变仪表自身的输出状态。

## 协议与兼容

协议依据本地《RD105_SPEC 通讯协议 v1.3.0》与实体只读应答。现场固件的 `INQUIRE=1@` 返回含 TC1/TC2 的多条记录，其中 TC2 为零占位；`OK:FPV=4370@` 带可选冒号，应答还包含 NUL、CR/LF。解析只接受所请求的字段，不能把命令回显、零占位或 UART 写入 ACK 当作设备确认。

现场 Modbus FC03 能读型号和固件，但读取 `0x1000 / count=4` 只返回 4 字节目标温度，与新版通用寄存器批量读取约定不同。当前 GPIO 业务使用 ASCII 查询及写后独立查询确认，不沿用旧 6A 参数事务。目标和实测温度按原厂整数除以 `100000` 转为摄氏度；占空比使用 `PWMDUTY / 20000` 转为百分比。周期采集使用 `DATADEMAND=1@` 等轻量查询，完整参数逐字段读取，避免旧固件 `INQUIRE` 长应答在 USB 延迟期间填满 256 字节 UART FIFO。

两台独立仪表的公共参数不能默认为共享状态。未读到的值显示不可用；TTL 的实际 38400 波特率不用于猜测仪表另一接口的 RS485 配置。修改通信参数、恢复出厂及不能可靠确认的命令不会通过该路径执行。写超时或读回不一致会报告执行结果未知，不会自动重发仪表写入。

只有一路在线时仍可使用该路，连接详情逐口报告状态，离线通道的测量值为不可用；公共参数只在两台均在线且读回一致时有效。补接或排查接线后，历史错误标志与计数保留，通过本次事务的计数增量和逐字节错误位判断新错误，不因已有粘滞标志永久拒绝连接。重新连接时，若 UART 正在收发或仍有待发字节，上位机会停止本次连接。若 UART 已空闲但留有旧应答，上位机会记录端口和残留字节数，停用 UART 后确认接收队列为空，再发起新的型号查询。

## 本地、远程与记录

本地与 SkyCore 均复用同一 FPGA USB 会话；远程仍走既有数传 TCP。`uart_exchange` 只传递指定 LC0/LC1 的原始字节，业务层另行校验应答。批量发送独立 VLP 寄存器请求减少字节间 USB 往返，RX FIFO 弹出读取禁止自动重试，避免重复消费或丢失字节。

温度经既有 `TemperatureControllerData`、温控遥测及语义记录字段传输，时间为主机收到样本的时间，不伪造 FPGA 温度测量帧或设备采样时刻。原始 USB/VLP 命令和响应继续进入 FPGA 会话归档。历史 RD105 命名与旧文件的读取兼容保留。

旧 `0x4A / 0x6A00` RS485 模块仍存在于现有 BIT，但现场温控入口不启用它，也不向它发送仪表事务。设备概览使用 `0x48` 单独连接原位 TEC103，使用 `0x49` 单独连接遥测 TEC103。两个胶囊各自显示连接和数据状态，已识别但没有有效温度时显示黄色。`0x4A` 保留给显式双机操作及旧记录。AI8 的 CON19 RS485 路径不受影响。[旧 RD105 实现记录](rd105.md)用于追溯，不作为现场接线或通信参数说明。

本次复用已验证的 BIT，SHA256 为 `1fea4d82d598b95006c14551097d950887a8967e9ba8dc1b20480e6e13ff7513`。已有 68/69 原始 UART 满足接入需求，无需改 RTL 或重新生成 BIT。2026-11-15 因板卡电源或复位操作导致配置丢失，按后续授权将同一镜像重新加载到 SRAM，状态为 `0x109079fc`、DONE/EOS 有效。实体已完成身份、参数和温度的只读查询；输出、设温与 PID 的实际写入未作为本次硬件验证内容。

2026-11-15 补接第二台仪表信号线后，生产 Controller 连续取得两组双路有效样本。验收样本中，原位目标 27.3℃、实测约 53.81℃、原有输出开启且占空比 18%；遥测目标 26℃、实测约 23.36℃、原有输出关闭。两路均无新增丢字节、校验或帧错误，未发送仪表参数或输出写入，也未访问旧 6A 写通路。测试退出后恢复原来的 UART 与全局使能配置；原始诊断仅保留在本地，不纳入版本库。
