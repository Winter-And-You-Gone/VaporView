# EPSILON 实机验证备忘录

## 目的

记录当前无法仅凭厂商文档和通信例程定论的事项，供下次连接真实 EPSILON 后复核。验证前应以以下本地资料为准：

- `X:\Project\GPS\组合导航\用户通信例程202601`
- `X:\Project\GPS\说明书_文档\EPSILON使用手册V1.2_20250424.pdf`
- 当前项目中的 EPSILON 报文频率配置和串口命令实现

## 待实机确认事项

### 1. `#fmsg` 支持的报文频率

厂商通信例程只定义以下频率：

`0 / 1 / 2 / 5 / 10 / 20 / 50 / 100 / 200 Hz`

当前项目的普通报文频率列表存在以下差异：

- 遗漏厂商例程中的 `200 Hz`。
- 增加了 `250 Hz` 和 `500 Hz`。
- `MSG_IMU` 还增加了 `1000 Hz`。

目前不能确定这些差异属于新固件扩展，还是项目白名单错误。不要仅根据现有代码或旧版例程删除或保留这些值。

### 2. `#fantearm` 是否需要保存配置或重启

EPSILON 手册中 `#fantearm` 所在页面没有像 `#fmsg`、`#fparam` 那样明确标注“重启生效”。因此，当前项目在下发杆臂参数后执行保存或重新配置的流程，不能仅凭文档判定为错误。

需要实机确认以下行为：

- 命令成功后参数是否立即生效。
- 是否必须执行保存命令才会持久化。
- 设备重启或断电重上电后参数是否保留。
- 固件是否返回可用于区分“已接收”“已生效”“已保存”的回执。

## 下次检查步骤

### 准备信息

1. 记录 EPSILON 型号、硬件版本、固件版本和主串口波特率。
2. 保存测试前的报文频率配置和主天线杆臂参数。
3. 确认测试串口没有被 VaporView、串口工具或 RTKLIB 同时占用。
4. 保留完整串口收发日志和主机时间戳。

### `#fmsg` 频率验证

对普通报文分别测试 `200 Hz`、`250 Hz`、`500 Hz`，对 `MSG_IMU` 额外测试 `1000 Hz`：

1. 下发实际 `#fmsg` 命令并记录设备原始回执。
2. 连续采集至少 30 秒数据。
3. 按有效 FDILink 帧和设备时间戳计算真实输出频率，不只依据命令回执判断。
4. 记录丢帧、CRC 错误、串口队列溢出和输出抖动。
5. 重启设备后再次读取或测量频率，确认配置是否持久化。
6. 对比不同固件版本的结果，避免把单台设备结论直接推广到全部 EPSILON。

### `#fantearm` 生效和持久化验证

1. 读取或记录当前杆臂参数。
2. 下发一个容易识别且安全的测试值，并保存原始回执。
3. 不执行额外保存或重启，检查参数是否立即生效。
4. 若设备支持查询，读取参数回显；否则通过设备输出或厂商工具确认。
5. 重启设备后再次检查。
6. 恢复原始参数，并验证恢复结果。
7. 根据结果决定项目是否需要保存命令、重新配置或重启提示。

## 修改代码前的判断规则

- 设备拒绝某频率且多个固件版本结果一致：从项目白名单移除该值，并补充回归测试。
- 设备接受命令但实测频率不符：记录设备的实际限制，不把回执成功等同于配置生效。
- 只有新固件支持扩展频率：按固件能力区分可选项，避免对旧固件展示无效配置。
- `#fantearm` 无需保存或重启即可持久化：简化当前流程和提示。
- `#fantearm` 需要保存或重启：保留对应流程，并在 UI 中明确说明生效时机。

## 当前验证边界

### 分组参数设置实机检查

本次新增的安装与天线、导航融合设置需要补充以下验证。本地串口和远端天空链路分别执行，测试结束恢复原始设备参数：

1. 记录型号和固件，读取两组参数，保存原始值。分别核对 `AID_GYO_TRUN_ON_TARE_ENABLED`、`AID_GYO_TURN_ON_TARE_ENABLED` 的实际支持情况，不互相替代写入。
2. 与厂商上位机逐项对照安装角、主天线杆臂、副天线向量和双天线航向偏角的轴向及单位。双天线基线保持只读；未知动力学枚举保持禁用。
3. 修改一个可恢复参数，检查只写变化项、保存回执以及写后回读；重启后重新读取，确认持久化与导航输出恢复。回执成功不能代替重启验证。
4. 在安全条件下检查不支持参数、写入拒绝、断连和退出配置失败的提示；确认没有假成功、错误零值或自动重复写入。
5. 检查配置期间禁止开始录制、正在录制或暂停录制时禁止配置；完成配置后检查导航输出和录制杆臂元数据。
6. 记录两组读取、单项/多项保存与设备重启的实际时间，以固件和串口条件校核远端超时余量。

本轮没有连接真实 EPSILON，尚未验证串口命令回执、固件版本差异、极限输出频率以及 `#fantearm` 的实际生效和持久化行为。以上事项在完成实机测试前均应保持为待确认状态。

### 高级设置与静态维护实机检查

当前界面已扩展为五个子页、八组白名单参数。下面各项需分别通过本机串口和远端天空端执行，记录原值并在结束后恢复；软件模拟只证明处理逻辑，不证明设备效果。

1. **端口与型号**：记录完整型号、固件、连接端口及唯一 Main 所在端口。确认 COMM1 保持只读，Main 所在其它端口的波特率/协议修改也被拒绝。仅在可恢复的非控制端口验证波特率、RTCM/NMEA/外部协议和重启回读；未知枚举必须保留可见原值并禁止写入。
2. **NMEA**：核对 `MSG_OUT_NMEA` 实际枚举，测量 GGA 等输出频率。它与 `#fmsg` 包率不是同一接口，命令接受不代表高频输出能力。
3. **滤波、量程、PPS**：逐项核对单位、量程枚举及 GPIO2 可用性。GPIO1 的内部 GNSS PPS 只读取、不修改。滤波变更后结合实际振动和频谱验证，不把“0 关闭”扩展为所有字段都可写零。
4. **初始状态、参考点**：确认姿态零值恢复默认及其融合依赖，不自动关闭磁/重力辅助。参考点以 IMU 坐标系 XYZ 米验证位置、速度输出变化，并与天线杆臂区分；四个原点拆分键保持只读，采集负经纬度及负零附近的厂商回读样例后再定义编辑规则。
5. **外部辅助与里程计**：确认设备支持的端口协议、真实输入帧、坐标系、时标和质量字段。核对 `ODOM_TYPE` 参数枚举与 FDILink 里程计输入报文 TYPE 的不同含义；测试速度、左右轮刻度与杆臂，不把 AID 打开等同于输入已接通或自动校准已完成。
6. **配置快照**：导出真实成功读取值，与厂商工具对照；在同型号/固件的新会话中先读取当前组再导入。验证差异预览、只填编辑器、只写变化项，未知、未读、只读及不支持项不会写入。恢复原值后重启回读。
7. **静态维护**：水平静止执行调平/加表静态零偏，静止执行陀螺静态零偏，记录发送事实、动作回执、保存回执、退出与导航恢复。无动作回执只报告已发送未验证；即使有 ACK 也不报告物理校准成功。重启后检查实际姿态/零偏效果，再决定是否重复，禁止自动重发。
8. **故障和时间**：在安全环境检查保存失败、退出失败、已发送后断连、导航恢复失败和设备重启失败；确认待重启事实保留、不混入另一个动作/会话的响应。记录最长分组读写时间，核对远端超时与录制互斥。

### D4G 内置差分与磁校准实机检查

已确认用户设备为 D4G，固件版本和本机连接状态尚未确认。D4G 字符串配置、ASCII 磁 2D/3D 与版本报文已接入；软件测试仅验证处理逻辑。

1. 先读取 `MSG_VERSION` 0x39；记录硬件/固件名称、原始编号、序列号及实际产品铭牌，确认 EPSILON 固定 40 字节布局。没收到报文时不猜型号或版本。
2. 按真实固件读取全部 9 个 DGNSS 字段，核对全角/半角分隔、空值、遮罩值与支持情况。`RTCM_TYPE` 保持只读，确认官方表 NTRIP=2 与示例3的冲突后才另行开放模式切换；不要与 `BASE_STATION_SOURCE` 混用。
3. 原值备份仅保存在本机，逐个检查 NTRIP/云字符串差异写、保存 ACK、回读、重启后值和设备真实网络/RTCM状态。模式没有改变或 RTCM 尚未连接不能报告差分服务已就绪。验证主机转发与内置通路不会重复注入。
4. 避开磁干扰，读取磁融合原值并记录实际 `MAG_3D` / `MAG_V` 键；2D 在水平面缓慢旋转一周，3D 改变姿态画空间∞字。捕获拆包状态、2D 100%、3D 有限误差小于3且High及自动退出后的导航帧。启动 ACK 不代表完成。
5. 检查原融合值恢复、Flash 保存和重启后的磁效果；取消、超时及断连后确认设备是否真实停止、导航是否恢复，不能仅凭退出请求认定停止。恢复失败时使用厂商工具核对；未核对前不重复校准。
6. 分别测试本地、远端与 IPC 的进度、取消、不同客户端不能取消别人的请求、断连/换目标晚响应隔离、录制互斥和停机退出。确认远端420秒超时覆盖300秒轮询及前后恢复，而不重复发送动作。

双天线和里程计自动向导仍缺少厂商扩展协议帧契约，已有手动参数不替代这些自动流程。取得相匹配的 MAVLink 扩展生成定义或完整 FDILink/ASCII 契约后，记录开始、进度、完成、停止及断连原始帧。详见 [实现与剩余清单](epsilon_settings_plan.md)。
