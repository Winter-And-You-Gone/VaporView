# RD105 激光温控接入（2026-11-15）

设备协议依据为光测未来《RD105_SPEC 通讯协议 v1.3.0》。直连串口与 FPGA 中转共用现有温控面板、状态结构和记录字段；本轮新增生产固件的独立 RD105 接口，保留 LC0/LC1、HC2A、SDFM300 和 AI8 的既有映射。

## 接线和通信

直连支持本机或天空端串口，RD105 出厂 TTL 为 38400/8N1，RS485 为 9600/8N1、站号 1。VaporView 的串口参数必须与实体设备一致，连接前会检测实际响应。

FPGA 路径使用 CON19 的 RS485 收发器，与 AI8 共享总线；当前 HC2A 继续使用独立 UART。接入前通过外部工具将实体 RD105 的 RS485 配置为 **19200/8N1、站号 2**，原厂波特率枚举为 2。AI8 保持站号 1；兼容 HMP 配置使用站号 240。FPGA 寄存器配置不会替实体设备修改通信参数。RS485 A/B/公共参考地、极性、终端和偏置按硬件接线要求核对，TTL 引脚不能直接接 RS485。

| 设备 | source | 寄存器页 | 模块 ID |
|---|---|---|---|
| RD105 | `0x004A` | `0x6A00` | `0x004A0103` |
| LC0 | `0x0048` | `0x6800` | `0x00480100` |
| LC1 | `0x0049` | `0x6900` | `0x00490100` |
| AI8 | `0x0046` | `0x6600` | `0x00460200` |

新固件扩展字为 `0x3B`，其中 bit4 表示 RD105，bit1 保留 AI8 八路扫描。上位机同时检查能力位和 RD105 模块 ID。缺少能力位的旧 `0x29`/`0x2B` 固件继续禁用 RD105；历史 `0x48/0x6800` RD105 设计不作为生产控制路径，也不向 LC0 发送温控命令。更新地面端时，远程 FPGA 路径的天空端 SkyCore 也必须同步更新。

读取历史保存配置时，将旧 `sensorParameters[72]` 中已知的 RD105 通道预设迁至 `sensorParameters[74]`，地址采用共用总线要求的 2；已有新源预设优先。迁移只作用于配置文件，不接受发往 `0x48` 的实时温控命令，也不会替实体 RD105 修改站号或波特率。

## 连接、数据显示和控制

首页和设备配置页的 RD105 按钮支持本地 FPGA、经现有数传 TCP 的远程 FPGA，以及原有直连串口。选择 RD105 不启用 LC0/LC1 或其他传感器。连接过程读取状态、校验配置并启用采集；连接、采集启用和有效测量分别显示，不能把 USB 打开或 CONTROL=1 当作设备应答成功。

两通道自动轮询。每帧 source `0x4A`、message `0x1100`、schema 2，含目标温度 `0x14`、实际温度 `0x15`（I32 微摄氏度）、错误 `0x02`（U32）、通道 `0x0480`（U32 1/2）、输出占空比 `0x0481`（I32）和输出使能 `0x0482`（U32 0/1）。原厂温度单位 0.00001℃ 转换为微摄氏度时乘 10；占空比原值除以 20000 得到百分比，保留正负方向。两通道分别合并显示、计算帧频和处理过期数据。

设备配置中的 RD105 频率草稿对应 `0x6A2C` 轮询间隔，连接时写入并核对，周期刷新保留未提交草稿。实际每通道频率还包含共用总线占用及 Modbus 事务耗时。高级参数中的“设温通道” `0x6A1C` 只选择简易设温动作的通道，两路自动采集持续运行。完整温控面板按通道的实体 Modbus 地址操作，不切换或停止扫描来模拟第二通道。

温控面板的“读取参数”读取两通道及通用配置；目标温度、输出使能、模式、限幅、PID、过温阈值、斜率、启动延迟、传感器参数等沿用既有协议校验。命令通过 `0x6A80` 参数事务传输 Modbus FC03/FC10，写入之后独立 FC03 读回，必须完成计数推进、状态成功且实际读回一致才显示成功。写 ACK 不等于执行完成；超时、CRC/设备异常或读回不匹配均不会自动重写。自整定值可能立即变化，读回不一致会显示失败，需要核查设备实际状态，不能重复启动来取得相等值。

FPGA 路径禁用改实体站号、改波特率和恢复出厂，底层同样拒绝相关寄存器及跨越这些地址的写入。直连原有维护入口保留。连接或开启采集不自动改设温、输出使能、模式或 PID。**断开 FPGA 采集只停止通信，不保证关闭实体 RD105 已开启的输出**；实体上电输出策略由温控器自身配置决定。

## 日志、记录和兼容性

RD105 的连接和失败日志标记 `fpga_source=0x4A`（结构化数值为 74），与 LC0/LC1 分开。SkyCore 的设备状态清单包含 RD105，双通道温控状态继续走既有遥测结构；断开清除采集状态。

温控快照继续使用语义字段 `laser_temperature_controller` 和 `sensors/laser_temperature_controller.csv`，不创建与直连不同的公共数据格式。原始 FPGA 帧和控制命令进入既有 VLP 会话归档，可回放和诊断；不能把 FPGA 解码后的温度快照宣称为原始 Modbus 串口帧。旧 `rd105` 命名文件的只读导入保持兼容。

协议模拟器默认使用 `Rd105Integrated`（`0x3B`）；`CurrentHcd2`（`0x29`）、`Hcd2Ai8Scan`（`0x2B`）保留为旧固件回归配置。`HistoricalExtensions` 仅用于额外 AI8 参数接口的兼容测试，其 RD105 也使用独立 6A 页，不恢复与 LC0 冲突的写入路径。

本轮为本机软件测试及下位机离线仿真、实现验证，未连接实体设备、未烧录板卡。测试和构建结果见本轮交付记录；实物温控响应、总线接线和通信预配置仍需在设备上电后验收。

## 上位机验证记录

在 VS/MSVC Developer 环境使用 `cmake --build build/Release --config Release --parallel 6` 完整构建成功，生成新版 VaporView 和 SkyCore。沿用本机已有地图开关，本轮没有修改地图依赖。更新旧固件/设备数量断言后完整构建成功；最后补充历史预设迁移，并针对最终应用代码再次完整构建和全量回归。

执行 `ctest --test-dir build/Release -C Release --output-on-failure --parallel 2`，178 项中初次 168 通过、9 失败、1 跳过，耗时 1087 秒。三项相关失败是旧断言：远程流程仍断言 RD105 不支持、刷新和输出控制回归将独立电机混入九个常规设备。更新这些断言，并加入真实 SkyCore TCP 双通道遥测及通道 2 负温设温读回验证后，`remote_connection_workflow_test`、`fpga_refresh_budget_test`、`fpga_sensor_draft_ui_test` 全部通过。日志存储故障上下文测试在全量时出现一次额外异步诊断，未改其源码，单独复测 `sky_fpga_storage_failure_context_test` 通过。四项最终复测使用同一 `build/Release`、`--parallel 1`，合计约 70 秒。

综合全量和最终复测，172 项通过、5 项已有失败、1 项权限分支跳过，不能宣称全量全绿。保留失败为 `temperature_controller_panel_test`（旧单图高度）、`main_window_layout_test`（温控概览高度）、`device_config_layout_test`（已移除的电机连续控制）、`ui_test_mode_window_test`（温度时间轴）和 `main_window_session_viewer_test`（偏心拖拽）。这些断言在本次接入前已复现，本轮不修改相应布局、运动控制或拖拽实现。

历史预设迁移补丁后的最终全量回归为 178 项：171 通过、6 失败、1 跳过，耗时 1008 秒。除上述五项已有失败，`remote_connection_workflow_test` 的连接动画响应时间 p95 为 101 ms，超过既有 100 ms 阈值；连接已完成。保持代码和阈值不变，单独复测约 24 秒通过，其中包含真实 SkyCore TCP 双通道采集和通道 2 负温设温读回。综合最终全量与该复测，结果仍为 172 通过、5 项已有失败、1 跳过；迁移的配置校验、优先级、LC 命令隔离和遥测回归均通过。

直接验证还包括：RD105 两通道与有符号占空比、手册温度边界/精度、下位机 schema2 黄金向量、独立 ID/能力门控、旧固件拒绝、LC 页隔离、设温与参数实际读回、错误/超时/不匹配不算成功、维护操作不发送、轮询草稿提交、延迟参数快照与较新实时温度合并、SkyCore 状态列表和断开失效。记录、会话回放、数据查看器、串口直连协议与其他 FPGA 功能复用全量中的有效通过结果。本轮测试使用隔离设置和测试进程，未连接硬件或修改实体参数。
